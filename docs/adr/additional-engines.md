# ADR: motores vLLM, Strata e PolyStrata ao lado do llama.cpp

Status: aceito em 2026-11-08

O launcher passou a executar modelos que o llama.cpp não atende: pastas Hugging Face (safetensors, AWQ, GPTQ) pelo vLLM, e os modelos do Strata (Niko1221/Strata) e do PolyStrata (simplexai-labs/PolyStrata). O registro em `src/engines.ts` descreve cada motor (plataformas, recursos, caminho da interface), detecta a instalação, lista os modelos que ele aceita e monta o comando do servidor. O motor é deduzido do formato do modelo e gravado no perfil; o llama.cpp continua em `src/engine.ts` com os binários oficiais fixados.

- **vLLM** fica fixado em `VLLM_VERSION` (0.32.0, a última release estável; 0.33.0 ainda era rc). No Linux o launcher cria um venv próprio e roda `pip install vllm==VERSION` (as wheels do PyPI são só CUDA; AMD ROCm exige um ambiente preparado pela documentação do vLLM), ou aceita um ambiente com `bin/vllm`. A varredura reconhece o cache do Hugging Face (links simbólicos para `../../blobs`); no Docker monta a raiz `models--org--nome`. No Windows não há build nativo; usamos a imagem `vllm/vllm-openai:vVERSION` pelo Docker Desktop (WSL2 + GPU), com o modelo montado só para leitura, `HF_HUB_OFFLINE=1`, um contêiner com nome próprio e `docker stop` ao parar. macOS fica de fora (só CPU, lento). GGUF no vLLM é experimental e não é oferecido.
- **Strata e PolyStrata** compartilham `serve/server.py --engine strata --config strata-<modelo>.json`. O launcher só aponta para uma pasta já instalada pelo instalador oficial deles (que baixa dezenas de GB e compila ou baixa o motor por GPU); não roda `install.ps1 | iex` nem `setup.sh`. Cada `strata-*.json` é um modelo; contexto, quantização e GPU vêm dele. Só o servidor do Strata aceita `--parallel`; no PolyStrata vale o `parallel` da configuração. No Windows, a regra de firewall usa o Python base lido de `.venv/pyvenv.cfg`, porque `Scripts\python.exe` é só um lançador. Windows e Linux; o suporte a Mac deles é beta e exige compilar na máquina.
- A chave de API vai por variável de ambiente (`VLLM_API_KEY`, `STRATA_API_KEY`), nunca na linha de comando. Acesso fora de `127.0.0.1` continua exigindo chave, e a ponte local autenticada vale para todos os motores.
- Benchmark, sugestão de ajustes, análise pelo modelo, conversa integrada e CLI dependem de `llama-bench`/`llama-cli` e ficam só no llama.cpp.
- Não validado em hardware real nesta versão: instalação do vLLM por pip, a imagem Docker com GPU e um servidor Strata/PolyStrata carregando um modelo. Os testes cobrem detecção, descoberta de modelos e os comandos gerados, e `npm run smoke:engines` cobre a interface com instalações simuladas.
